# 0.2.1 — 2026-10-25

## Added

- **Microwave paths** (FCC PA records) appear on `fcc_spectrum_get_license` under `locations[].antennas[].paths` with a top-level `pathTotal`, carrying the receive site, its coordinates when the license files one, and the receiver callsign. The location window adds a 100-path budget, and the license resource and `fcc_spectrum_list_reference` carry the same. Schema 8 adds a `paths` table and marks older generations path-coverage-incomplete: `pathTotal` is omitted and the notice discloses the gap until `bun run mirror:init` or the weekly rebuild fills it. [#27](https://github.com/cyanheads/fcc-spectrum-mcp-server/issues/27)

## Changed

- **Daily refresh** (`mirror:refresh` and the scheduled run) skips daily files of weekly groups the index does not hold before any request; `rb` files are never skipped. A paging-only index drops from 196 requests to 27. [#19](https://github.com/cyanheads/fcc-spectrum-mcp-server/issues/19)
- **Mirror CLI** moved from `scripts/` to `src/cli/` and compiles to `dist/cli/`; `mirror:init|refresh|verify` run `bun dist/cli/mirror-<name>.js`, so npm and `.mcpb` installs can run them. Run `bun run build` first in a checkout. The `.ts` scripts and the Dockerfile's runtime `tsconfig.json` are removed. [#31](https://github.com/cyanheads/fcc-spectrum-mcp-server/issues/31)
- **ReDoS-guard tests** in `tests/tools/input-schemas.test.ts` and `tests/services/uls/normalize.test.ts` measure thread CPU time instead of wall-clock time.
- **Framework maintenance** syncs `framework-skills/` and `scripts/devcheck.ts`.
